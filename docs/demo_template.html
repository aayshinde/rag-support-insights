A support-ticket triage system that knows when not to answer.

It searches 48,178 past tickets, drafts a next-best-action with a local LLM, and escalates to a human whenever the retrieved evidence is too weak to trust. This page is built from its real results on tickets it never saw.

How a message flows through it

The confidence gate is the new part. It reads the retrieved tickets, predicts the chance that the triage is correct, and decides before the LLM is called.

Drag the threshold. See the trade-off.

Every point on the curve is a threshold. Answering more queries means more wrong answers. The gate picks a point on this curve instead of answering everything.

What I found

All numbers are measured against gold category labels, so no LLM judge is involved. The confidence model was fit on leave-one-out queries from the knowledge base and tested on the held-out split.

Raw similarity is a poor trust signal

Area under the risk-coverage curve on held-out queries. Lower is better.

Raw top-1 similarity is worse than random. Neighbour agreement does nearly all of the work, and the calibrated model adds a small edge and a usable probability.

The data hides two different problems

Where the knowledge base runs out

Clustering the queries the gate escalates shows which topics the system cannot handle. Low category purity means the same topic is filed under many categories, which points to a taxonomy problem as well as missing knowledge.

    Run it yourself

    Everything runs locally with no API key and no cost.

    python -m venv .venv && source .venv/bin/activate && pip install -r requirements.txt
brew install ollama && ollama pull llama3.2:3b && ollama pull nomic-embed-text
python -m src.data --source both     # download and split the datasets
python -m src.ingest                 # embed 48K tickets into FAISS
python -m src.reliability            # fit the confidence gate, write the report
streamlit run app.py                 # live dashboard
